# Repository Guidelines

SkitourSafe is an **Astro SSR app** (React 19 islands, Tailwind CSS 4, Supabase auth, shadcn/ui) deployed to **Cloudflare Workers**. Product docs live in `context/foundation/` — read `@context/foundation/prd.md` and `@context/foundation/tech-stack.md` before starting feature work.

## Critical rules

- **No test suite exists.** There is no `npm test` and no test runner installed. Verify changes with `npm run lint`, `npx astro check`, `npm run build`, and `npm run smoke`.
- **zod is not a dependency.** Do not add or import it. API routes read `await context.request.formData()`; React islands validate inline (regex / length) before posting.
- **Never hand-edit `.github/copilot-instructions.md`** — it is generated by `@przeprogramowani/10x-cli` and rewritten between the `BEGIN`/`END` markers.
- **Do not add `export const prerender = false` to routes.** The app is fully on-demand; that flag is only for opting a route _into_ static prerendering.
- **CI is configured for `master`, but the working branch is `main`.** Pushes and PRs targeting `main` do not trigger `.github/workflows/ci.yml`.
- These do **not** exist yet — create them only when the work needs them, following the conventions below: `src/types.ts`, `src/lib/services/`, `src/components/hooks/`, `supabase/migrations/`.

## Architecture

- `output: "server"` in `astro.config.mjs` with the `@astrojs/cloudflare` adapter — every page renders on request.
- Env vars are declared as **server-only secrets** in `astro.config.mjs` (`env.schema`) and imported from `astro:env/server`: `SUPABASE_URL`, `SUPABASE_KEY`. Never read them from `import.meta.env`, never send them to the client.
- `createClient(headers, cookies)` in `src/lib/supabase.ts` builds the cookie-based `@supabase/ssr` client and **returns `null` when the env vars are missing**. Every call site must handle the null case (see `src/middleware.ts`, `src/pages/api/auth/*.ts`, `src/lib/config-status.ts`).
- `src/middleware.ts` resolves the Supabase user into `Astro.locals.user` (typed in `src/env.d.ts`) and redirects unauthenticated requests whose path starts with an entry in `PROTECTED_ROUTES`. Add new protected paths there, not in per-page guards.
- API routes live in `src/pages/api/**` and use uppercase verb exports: `export const POST: APIRoute = async (context) => { … }`.
- Auth errors are **not** returned as JSON. Routes redirect back to the form with `?error=<url-encoded message>`; the page reads `Astro.url.searchParams.get("error")` and passes it to the island as `serverError`.
- Foundation-doc conventions (edit in place, archive to `foundation/archive/YYYY-MM-DD-<doc>.md`) are in `@context/foundation/README.md`.

## Conventions

- **Path alias**: `@/*` → `./src/*`. Always import internal modules through it, never relatively.
- **Astro for structure, React only for interactivity.** Islands are hydrated explicitly (`client:load`) and must not use Next.js directives such as `"use client"`.
- **Tailwind classes**: merge conditional class names with `cn()` from `@/lib/utils`. Never concatenate class strings by hand.
- **shadcn/ui**: primitives belong in `src/components/ui/` ("new-york" style; aliases in `components.json`). Add new ones with `npx shadcn@latest add <name>` instead of hand-copying them.
- **File layout**: generic Astro components directly in `src/components/`, feature-scoped components in a feature folder (`src/components/auth/**`), shadcn primitives in `src/components/ui/`, helpers and integrations in `src/lib/`.
- **Props**: declare a local `interface Props` and destructure it from `Astro.props` (Astro) or from typed function parameters (React).
- **Supabase migrations** (when introduced): `supabase/migrations/YYYYMMDDHHmmss_short_description.sql`, with RLS enabled on every new table and granular per-operation, per-role policies.
- **Commits** use the course-lesson prefix form: `m<N>l<M> - <short summary>` (e.g. `m1l3 - bootstrap`).

## Environment

- Node.js v22.14.0 (see `.nvmrc`).
- Secrets: `SUPABASE_URL`, `SUPABASE_KEY` — `.env` for Node, `.dev.vars` for Cloudflare local dev (gitignored). Full setup in [README.md](./README.md).
- Deploy with `npx wrangler deploy`.

## CI

`.github/workflows/ci.yml` (triggers on `master` only — see Critical rules) has two jobs:

- **ci** — `npm ci`, `npx astro sync`, `npm run lint`, `npx astro check`, `npm run build` (needs `SUPABASE_URL` / `SUPABASE_KEY` repository secrets).
- **smoke** — starts a local Supabase, builds, serves the production preview and runs `npm run smoke` against it (no secrets required).

## Gotchas

- User-facing copy is **mixed**: starter messages (`src/lib/config-status.ts`, `src/layouts/Layout.astro`, `src/components/Banner.astro`) are Polish, while the auth/dashboard demo copy is English. Match the surrounding language when editing an existing view.
- `src/layouts/Layout.astro` renders config-error banners automatically from `missingConfigs`, so a missing Supabase config is surfaced to the user instead of crashing.
- `scripts/smoke.mjs` is dependency-free and covered by a dedicated `scripts/**` block in `eslint.config.js` (type-checking off, `no-console` off). It is a starter sanity check, not a real test suite.
- `.github/skills/10x-*` and `.github/.10x-cli-manifest.json` are managed by `@przeprogramowani/10x-cli`. Do not edit them by hand; the CLI overwrites them on update.
- README's "Project Structure" block lists `src/assets/` — that directory does not exist.
